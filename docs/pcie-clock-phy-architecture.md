## 一、两种 PCLK 时钟架构

PCIe 规范定义了两种参考时钟方案，核心区别在于**链路两端的参考时钟是否同源**。

```
Common Clock (共享时钟)                    SRIS (独立时钟)
────────                                   ──────

┌──────────┐    refclk 100MHz             ┌──────────┐  refclk_1 100MHz
│  晶振/    │────┬────────────► RC         │  晶振 A  │──────► RC
│  Clock    │    │                        └──────────┘
│  Buffer   │    │ refclk 100MHz          ┌──────────┐  refclk_2 100MHz ±300ppm
└──────────┘    └────────────► EP         │  晶振 B  │──────► EP
                                          └──────────┘
  两端同源，频率锁定                         两端独立，频率有偏差
  SSC 共享（同相）                           SSC 各自独立
```

### 1.1 Common Clock（共享参考时钟）

**工作原理**：链路的 RC 端和 EP 端共享同一个 100MHz 参考时钟源（通过时钟 Buffer 分发）。两端的 PLL 锁定在同一频率上，SSC（展频时钟）也同相。

**优点**：

| 优点 | 说明 |
|:---|:---|
| **时钟恢复简单** | 收发两端频率完全一致，CDR 只需跟踪相位变化，不需要跟踪频率偏差 |
| **弹性 Buffer 深度小** | 因为频率锁定，收发速率完全相同，elastic buffer 只需处理 ±1-2 UI 的相位漂移，通常 16-32 entry 即可 |
| **确定性延迟低** | 不需要频繁插入/删除 SKP Ordered Set，链路延迟更稳定 |
| **SSC 同步** | 两端同时做展频，接收端 CDR 可以精确跟踪 SSC 调制信号 |
| **兼容性最好** | 所有 PCIe 设备都支持，早期规范（Gen1/2）的主要方案 |
| **抖动预算宽松** | 因为低频抖动（SSC）是同相的，高频随机抖动也更容易跟踪 |
| **功耗略低** | CDR 不需要追踪 ±300ppm 的频率偏差，PLL 锁定更轻松 |

**缺点**：

| 缺点 | 说明 |
|:---|:---|
| **需要时钟布线和分发** | PCB 上需要额外的差分时钟线，占用面积和层数 |
| **不适合长距离/跨板连接** | Refclk 信号质量随距离衰减，跨背板或跨机箱时抖动恶化 |
| **单一时钟源故障风险** | 如果 refclk 出问题，整个链路失效 |
| **时钟 Buffer 增加成本** | 每个端口需要独立 refclk 输入或通过 Buffer 扇出 |
| **芯片 Pin 消耗** | 每个 PCIe 控制器需要 2 个 refclk 差分 pin（除非共用） |
| **SSC 必须同源** | 如果需要展频，所有共享 refclk 的设备必须用同样的 SSC profile |

### 1.2 SRIS（独立参考时钟 + 独立展频）

**全称**：Separate Reference Clock with Independent SSC (SRIS)，在 PCIe Base Spec 2.0（2007年）引入。

**工作原理**：RC 和 EP 各自使用独立的参考时钟源（各自板上的晶振），各自的 SSC 调制也是独立的。接收端 CDR 需要同时追踪频率偏差（±300ppm）和相位变化。

```
发送端：用自己的 refclk_1 + 自己的 SSC profile
接收端：用自己的 refclk_2 + 自己的 SSC profile
       接收端 CDR 必须容忍：refclk_1 和 refclk_2 的频率差 + 两个 SSC 的调制差
```

**优点**：

| 优点 | 说明 |
|:---|:---|
| **不需要共享 Refclk** | 省去时钟布线和分发，PCB 设计极大简化 |
| **适合长距离/跨板连接** | 两个设备可以完全独立，refclk 不需要跨系统传输 |
| **低引脚数** | 不消耗 refclk pin，对小型封装（如 M.2、U.2）至关重要 |
| **独立 SSC** | 每个设备可以用不同的展频参数，甚至一个开一个关 |
| **系统级简化** | 减少了系统级的时钟拓扑依赖，架构更模块化 |
| **适合可插拔设备** | M.2 SSD、U.2 盘、外置 GPU 盒等场景的唯一选择 |

**缺点**：

| 缺点 | 说明 |
|:---|:---|
| **CDR 复杂度高** | 需要追踪 ±600ppm（两个 ±300ppm 叠加的最坏情况）的频率偏差，对 CDR 设计挑战大 |
| **弹性 Buffer 深度大** | 发送和接收之间有持续频率差，elastic buffer 必须足够大来吸收，通常 128-512 entry |
| **延迟/确定性差** | 频率偏差导致周期性 SKP Ordered Set 插入/删除，引入延迟抖动 |
| **对 SSC 敏感** | 两个独立的 SSC 信号叠加可能导致更大的时钟抖动 |
| **兼容性问题** | 不是所有设备都支持 SRIS；早期 Gen1 设备不支持 |
| **Link Equalization 复杂** | 频率偏差使得链路均衡训练（Gen3+ 的 Equalization Phase）更容易失败 |
| **功耗略高** | CDR 需要更大的锁定范围和动态响应 |

### 1.3 对比表

| 维度 | Common Clock | SRIS |
|:---|:---|:---|
| **参考时钟** | 共享同一 100MHz 源 | 各自独立 100MHz ±300ppm |
| **SSC** | 共享（同相） | 独立（可能不同相） |
| **频率偏差** | ~0ppm（同源锁定） | 最大 ±600ppm（两个 ±300ppm 最坏叠加） |
| **CDR 难度** | 低（只追相位） | 高（追频率 + 相位） |
| **弹性 Buffer** | 16-32 entry | 128-512 entry |
| **SKP 插入频率** | 低（偶尔抖动吸收） | 高（每间隔周期性插入/删除） |
| **PCB 布线** | 需要 refclk 差分线 | 不需要 refclk 线 |
| **Pin 消耗** | +2 pin (refclk±) | 0 |
| **延迟抖动** | 低 | 较高 |
| **适合场景** | 板上互联、芯片间 | M.2/U.2/O CuLink/跨背板 |
| **规范要求** | PCIe 1.0+ | PCIe 2.0+ |
| **BOM 成本** | 需要时钟 Buffer | 省去时钟分发器件 |
| **菊花链问题** | refclk 分发复杂 | 天然支持 |

### 1.4 选型决策

```
你需要跨板/跨机箱连接吗？
  │
  ├── 是 ──► SRIS（M.2、U.2、外置设备）
  │
  ├── 否（板上连接）
  │     │
  │     ├── 引脚数紧张？──► SRIS
  │     │
  │     ├── 延迟敏感？────────► Common Clock
  │     │
  │     └── 一般的板上互联 → Common Clock（更可靠）
  │
  └── 混合系统（同一个 IP 两种场景都要支持）
        └── 两个模式都实现，通过寄存器切换
```

## 二、PHY 架构：Original vs SerDes

> 这里的 "Original" 和 "SerDes" 是芯片设计中常见的两种 PHY 实现方式，区别在于**宏架构**——时钟如何产生、如何分发到各 lane。

### 2.1 什么是 "Original" PHY 架构

**概念**：传统的 CMOS I/O 方式，每个 lane 有独立的 PLL 或者由一个全局 PLL 驱动 + 每个 lane 独立的 phase rotator（相位旋转器），lane 之间的时序通过共享参考时钟（refclk）来对齐。

```
Original PHY 架构
─────────────────

      ┌─────┐
      │ PLL │  ← 共享 100MHz refclk，倍频到 5/8/16/32 GHz
      └──┬──┘
         │ 高频时钟（通过 clock tree 分发到各 lane）
    ┌────┼────┬────┬────┐
    ▼    ▼    ▼    ▼
  ┌───┐┌───┐┌───┐┌───┐
  │L0 ││L1 ││L2 ││L3 │  每个 lane：Phase Rotator + TX Driver + RX CDR
  └───┘└───┘└───┘└───┘
    │    │    │    │
    ▼    ▼    ▼    ▼
  TX0  TX1  TX2  TX3
  RX0  RX1  RX2  RX3
```

**工作方式**：
- 一个中央 PLL 产生高频时钟
- 通过全局时钟树分发到每个 lane
- 每个 lane 用 **Phase Rotator**（相位旋转器）微调相位，补偿走线长度差异
- 接收端每个 lane 有独立的 CDR (Clock and Data Recovery)
- PIPE 接口是并行总线（8/16/32 bit），MAC↔PHY 通过并行数据交互

**优点**：

| 优点 | 说明 |
|:---|:---|
| **成熟稳定** | 最传统的实现方式，被验证了 20+ 年 |
| **Lane-to-Lane Deskew 简单** | 所有 lane 共享同一 PLL，lane 间偏斜主要由 PCB 走线差决定 |
| **PLL 噪声可控** | 单个 PLL 的相位噪声更容易分析和优化 |
| **功耗可预测** | 功耗模型简单，容易做 power gating |
| **支持多协议** | 同一个 PHY 可配置为 PCIe/SATA/USB3 等不同协议（通过 PIPE 切换） |

**缺点**：

| 缺点 | 说明 |
|:---|:---|
| **时钟树消耗** | 全局高频时钟分布到每个 lane 需要大量功耗和面积，随 lane 数量线性增长 |
| **高频时钟分布难** | Gen4 (16Gbps) 以上，时钟树上的 skew 和 jitter 变得严重 |
| **Lane 间耦合** | 中央 PLL 的噪声会耦合到所有 lane，一个 lane 的 PLL glitch 影响全局 |
| **面积大** | 全局时钟树 + 每 lane 的 phase rotator 占用显著面积 |
| **扩展性差** | 从 x4 扩展到 x16 时，时钟树复杂度平方增长 |
| **PLL 锁定时间长** | 中央 PLL 锁定时间长，影响省电模式退出 |

### 2.2 什么是 SerDes 架构

**概念**：串行器/解串器架构。每个 lane 是一个独立、自包含的 SerDes 单元，有自己的 LC-PLL（电感电容 PLL）或 Ring-PLL。数据流完全串行化，时钟从数据流中恢复。

```
SerDes PHY 架构
─────────────────

  没有全局 PLL，没有全局时钟树

  ┌───────────────┐ ┌───────────────┐ ┌───────────────┐ ┌───────────────┐
  │   Lane 0      │ │   Lane 1      │ │   Lane 2      │ │   Lane 3      │
  │               │ │               │ │               │ │               │
  │  ┌─────────┐  │ │  ┌─────────┐  │ │  ┌─────────┐  │ │  ┌─────────┐  │
  │  │LC-PLL   │  │ │  │LC-PLL   │  │ │  │LC-PLL   │  │ │  │LC-PLL   │  │
  │  └────┬────┘  │ │  └────┬────┘  │ │  └────┬────┘  │ │  └────┬────┘  │
  │       │       │ │       │       │ │       │       │ │       │       │
  │  ┌────▼────┐  │ │  ┌────▼────┐  │ │  ┌────▼────┐  │ │  ┌────▼────┐  │
  │  │  TX     │  │ │  │  TX     │  │ │  │  TX     │  │ │  │  TX     │  │
  │  │(equaliz)│  │ │  │(equaliz)│  │ │  │(equaliz)│  │ │  │(equaliz)│  │
  │  └────┬────┘  │ │  └────┬────┘  │ │  └────┬────┘  │ │  └────┬────┘  │
  │       │       │ │       │       │ │       │       │ │       │       │
  │  ┌────▼────┐  │ │  ┌────▼────┐  │ │  ┌────▼────┐  │ │  ┌────▼────┐  │
  │  │  RX+CDR │  │ │  │  RX+CDR │  │ │  │  RX+CDR │  │ │  │  RX+CDR │  │
  │  └─────────┘  │ │  └─────────┘  │ │  └─────────┘  │ │  └─────────┘  │
  │               │ │               │ │               │ │               │
  │  完全自包含     │ │  完全自包含    │ │  完全自包含    │ │  完全自包含    │
  └───────────────┘ └───────────────┘ └───────────────┘ └───────────────┘
       │                   │                  │                  │
       ▼                   ▼                  ▼                  ▼
     TX0/RX0            TX1/RX1           TX2/RX2           TX3/RX3

  仅共享一个低频 refclk (100MHz) 给每个 lane 的 PLL 做参考
```

**工作方式**：
- 每个 lane 是完全独立的 SerDes 宏
- 每个 lane 有自己的 LC-PLL（共享 100MHz refclk 作为参考）
- 接收端 CDR 从串行数据流中恢复时钟
- 不需要全局高频时钟树，lane 之间相互隔离
- 通过 cross-lane training 来处理 lane-to-lane skew

**优点**：

| 优点 | 说明 |
|:---|:---|
| **无全局时钟树** | 不需要分发高频时钟，面积和功耗大幅降低 |
| **Lane 间隔离好** | 一个 lane 的 PLL 噪声不影响其他 lane |
| **扩展性好** | x4→x8→x16 只需例化更多 lane，线性扩展，没有时钟树瓶颈 |
| **功耗按需** | 每个 lane 可以独立关闭（power gating），未用 lane 完全不耗电 |
| **高频友好** | Gen5/Gen6 (32/64 GT/s) 没有时钟树 skew 问题 |
| **面积效率高** | 先进的 SerDes 宏在 FinFET 工艺下每个 lane 面积很小 |
| **快速锁定** | LC-PLL 锁定时间远快于大型中央 PLL，省电状态退出快 |
| **工艺移植容易** | 每个 lane 是独立硬核，从 7nm→5nm→3nm 只需替换 lane 宏 |

**缺点**：

| 缺点 | 说明 |
|:---|:---|
| **LC-PLL 电感面积** | 每个 lane 的 LC-PLL 需要片上电感，多个电感占用面积 |
| **Lane-to-Lane Deskew 复杂** | 没有全局 PLL，lane 间偏斜完全依赖训练（TS1/TS2 中的 Lane-to-Lane Deskew 机制） |
| **PLL 间频率差** | 各 lane 的 LC-PLL 可能微有频率差（通常在 100ppm 内），需要接收端弹性 Buffer 吸收 |
| **设计复杂** | 每个 lane 的独立 LC-VCO 需要仔细设计以避免 pulling 和 coupling |
| **电感耦合风险** | 相邻 lane 的片上电感可能互相耦合，导致 pulling（频率牵引） |
| **NRE/授权成本高** | 好的 SerDes IP 通常来自第三方（Synopsys/Cadence），授权费高 |

### 2.3 对比表

| 维度 | Original PHY | SerDes PHY |
|:---|:---|:---|
| **时钟架构** | 中央 PLL + 全局时钟树 + 每 lane Phase Rotator | 每 lane 独立 LC-PLL，无全局高频时钟 |
| **lane 独立性** | 部分独立（共享 PLL） | 完全独立 |
| **Lane 间耦合** | 较大（PLL 噪声共享） | 很小（仅低频 refclk 共享） |
| **高频时钟树** | 需要，随 lane 数增加 | 不需要 |
| **Deskew** | 简单（Phase Rotator 补偿） | 依赖链路训练（TS Ordered Set） |
| **扩展性 (x4→x16)** | 差（时钟树平方增长） | 好（线性扩展） |
| **功耗** | 全局时钟树功耗大 | 按 lane 独立控制，省电 |
| **高频适用性** | Gen1-4 为主 | Gen3-6，特别是 Gen5/6 |
| **面积** | 时钟树 + 各 lane 较大 | 电感 + 各 lane 紧凑 |
| **工艺依赖** | 较独立 | 强依赖工艺（LC-PLL 电感需要先进工艺） |
| **多协议支持** | 好（PIPE 接口灵活） | 好（每 lane 可独立配置协议） |
| **32G-PHY 兼容** | 困难（时钟 skew 严重） | 天然适配 |
| **成本** | 设计成本低，授权可选 | 授权费高（第三方 IP） |
| **PLL 锁定时间** | 较长 | 短 |
| **成熟度** | 非常成熟 | 已被主流 SoC 广泛使用 |

### 2.4 选型建议

```
你在设计哪个工艺节点？
  │
  ├── 28nm/40nm/65nm ──► Original PHY（工艺不支持高性能 LC-PLL）
  │
  └── 16nm/7nm/5nm/3nm
        │
        ├── Gen5+ 需求 ──► SerDes 架构（几乎必须）
        │
        ├── 需要多 lane (≥x8) ──► SerDes（扩展性好）
        │
        ├── 功耗敏感 ──► SerDes（独立 power gating）
        │
        └── 成本优先 + Gen1-4 ──► Original 也可以
```

## 三、对本项目的影响

`sys_pcie_eth_pwr_wrap` 使用 **32G-PHY（Gen5 ×4）**，这决定了：

| 架构选择 | 本项目的选择 | 原因 |
|:---|:---|:---|
| **时钟架构** | **SRIS 能力强** | 规范 §2.1 明确写了 "支持 SRIS"，32G-PHY 面对跨协议共享场景，SRIS 是必备 |
| **PHY 架构** | **SerDes 架构** | 32Gbps per lane × 4 lanes，在先进工艺下必须是 SerDes 架构；Original PHY 在 32Gbps 几乎不可行 |

**32G-PHY 的实现特征**（从 SerDes 架构推断）：
- 每个 lane 独立的 LC-PLL + CDR
- 接收端 CDR 必须支持 SRIS 的 ±600ppm 追踪
- Elastic buffer ≥ 128 entry（吸收 SRIS 频率偏差）
- 每 lane 支持独立的 TX equalization（FFE/De-emphasis）
- 每 lane 独立的 RX equalization（CTLE + DFE）
- Bifurcation 在 SerDes lane 层面做静态切换（mux 在 PCS 层）
